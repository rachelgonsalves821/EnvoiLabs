# ADR 0004. OpenVerbatim evidence location review

Decision for R-RSCH-08 and IT-3.2, 2026-11-23. Reviewed [OpenVerbatim revision `01d8dd70faf54f16a322f8275e61cb4ea20a52e0`](https://github.com/Vellum-Works/openverbatim/tree/01d8dd70faf54f16a322f8275e61cb4ea20a52e0), including [grounding](https://github.com/Vellum-Works/openverbatim/blob/01d8dd70faf54f16a322f8275e61cb4ea20a52e0/apps/server/src/codingGrounding.ts) and [coding](https://github.com/Vellum-Works/openverbatim/blob/01d8dd70faf54f16a322f8275e61cb4ea20a52e0/apps/server/src/coding.ts). Its repository [license at this revision](https://github.com/Vellum-Works/openverbatim/blob/01d8dd70faf54f16a322f8275e61cb4ea20a52e0/LICENSE) is Apache-2.0. No upstream code or media is included here.

OpenVerbatim distinguishes verbatim from loose or fabricated model suggestions, localizes a quote to an utterance and revision, and records suggestion and discard events. We adapt the provenance pattern with original Envoi code. A proposed quote carries its redacted transcript ID, immutable source version, Unicode character offsets, exact text, rationale and confidence. The evidence gate accepts only the exact substring of the current published redacted source for the same study. Re-redaction, withdrawal, deletion, unpublication or duplicate source records drop it. Findings without a supporting quote are withheld. The same gate must run on report and export reads, and its decisions must be written to an append-only audit store by the integration layer.

The original code accepts some approximate locations for suggested coding. Envoi report evidence uses exact spans only, as required by PRD 8.3. Researcher-visible data must come from the qualified redacted projection; raw transcripts must never be handed to this gate. Model-written rationales never appear in the published evidence shape. Model-written claims are withheld until the integration layer supplies text passed by the currently qualified publication policy; the pure helper has no access to that policy and cannot independently certify a claim. Database-backed source versions, current consent, report persistence, audit writes and read-time invalidation require a coordinated Platform projection and schema integration. The local IT-3.2 fixtures establish the pure integrity behavior, not the complete database or browser acceptance test.

The existing `research.findings` view exposes the stored `claim`, and `research.evidence_quotes` derives quote text from the current transcript using only offsets. Before report rows are made researcher-visible, Platform must gate stored claims and report summary fields through qualified redaction, store an immutable source version on each quote, and make the view suppress stale or withdrawn evidence. An API-only filter is insufficient while direct researcher SELECT grants remain.
