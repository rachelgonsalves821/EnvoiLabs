# Gate 3 pilot preparation

This is a synthetic rehearsal plan for an open, profile-matched marketplace. Gate 1 redaction qualification, the voice consent/data-handling decision and Gate 2 marketplace readiness must pass before Gate 3 fielding. No hand-recruited or invitation-selected first-study cohort is assumed.

## Probe timing evidence

For each eligible core-question answer, record upload confirmation, transcription completion, decision, and browser render times under the persisted turn UUID. Classify every attempt as rendered, intentional no-probe, error, timeout or superseded. A late probe is discarded once the next question is active. Use `summarizeProbeAttemptLog` to reject duplicate turns, keep fictional fixtures separate from physical-device captures and report overall plus iOS Safari and Android Chrome metrics. The device and evidence fields are caller-supplied labels, so retain the underlying capture/receipt evidence; the summary alone does not prove a device run. Time representative mobile browser recordings on physical iOS Safari and Android Chrome. Agree on an acceptable timeout rate before fielding; the six-second p95 applies from upload confirmation through browser render.

The AI-owned `decideProbe` advances to the next guide question on provider error, malformed output or timeout. Its turn ID protects against late results. The browser adapter must call `presentProbeIfCurrent` when mounting a probe and supply the same monotonic clock used at upload confirmation; the hook observes two animation frames and records render time. Count a superseded turn separately from an intentional no-probe decision. The eight-case fictional `probe-runtime` replay yields three rendered probes (p95 5,100 ms), one intentional no-probe, two errors, one timeout and one superseded turn. These fixture timings are labels, not measurements from a device or live provider.

The separate `probe-quality` replay now has 11 fictional answer/goal/decision labels: five acceptable neutral, on-goal probes, three expected next-question decisions, and three rejected probe examples (leading, off-goal and incomplete). The runner reports those categories independently. It also exercises a deterministic leading-question rejection in the runtime. These labels were authored as synthetic fixtures; they do not estimate live model quality. Before the PRD's probe-quality target is assessed, collect the planned 60 independently judged answer transcripts, define the neutral/on-goal rubric and disagreements, run the actual provider against held-out inputs, and report numerator, denominator and off-topic count.

## Probe state-machine handoff

`beginProbeTurn` and `advanceProbeState` model one answer's upload, transcription, decision and render with a unique turn ID, probe cap and deadline. Provider or transcription failure advances to the static next guide question. Current `InterviewView`/`AnswerComposer` only receive `SessionResponse.nextQuestion` and call `onSaved()` to reload the next core question. To integrate, Platform must expose a probe-aware, idempotent answer/turn read and decision write bound to `sessionId`, `guideQuestionId`, `answerId`, current transcript job/source revision, `maxProbes`, probes used, deadline, `probeId`, decision status and shown timestamp. The write must reject a decision for a superseded answer or question, a duplicate probe beyond the cap, and a result after the deadline. The respondent API should surface one current prompt (probe or next core question) with stable turn ID; browser code can then call `presentProbeIfCurrent` after confirmation and record the paint time. The upload confirmation and browser mark must use the same monotonic clock. Gate 1 consent and transcript availability still govern provider input. Until those fields and transitions exist, the synthetic state machine is not an integrated interview path.

The typed `ProbeDecisionPort` now defines `readReadyTurn`, compare-and-set `commitDecision`, and `markShown`. `readReadyTurn` must return a server-clock deadline, server upload confirmation time and transcript ready time; a separate browser monotonic confirmation time is echoed for the same-page render metric. It must also return the exact authorized model request and immutable transcript revision. Gate 3 re-reads and compares that snapshot after the provider returns, then commits only through the Platform compare-and-set. `markShown` receives the browser render measurement but must set database `shown_at` from the server clock after verifying the probe is still current. Browser and server timestamps must never be subtracted from one another. A page reload or a different device clock needs a fresh timing attempt or an unmeasured classification. The current Gate 1 APIs do not expose these fields or persist a probe decision; this remains a precise Platform request.

The port also needs `readCommitted(sessionId, turnId)`, scoped to a still-current authorized turn, returning `{sessionId,questionId,answerId,turnId,transcriptRevision,decision,probeId}`. A repeated delivery must return that decision without calling the model again. If another worker commits while one model call is pending, re-read the first writer's result and do not replace it. `commitDecision` must compare the session/question/answer/turn, immutable transcript revision, probe cap and deadline and be idempotent on the same key. It returns either the exact persisted decision and probe ID, `stale`, or `unavailable`; an uncertain write must not show generated text. `markShown` must be idempotent and reject a superseded probe. Gate 2 owns the contract, persistence and respondent UI, while Gate 3 owns this AI orchestration and will review the integration.

The browser presenter checks the active turn before mounting, waits for paint, then calls `markShown`. If the receipt is stale or unavailable it invokes the supplied retract callback and counts the attempt as superseded/error rather than rendered. The respondent UI must actually remove that probe on retraction and advance or retry according to its persisted current prompt; a stale receipt cannot leave text on screen.

The qualified report read port needs an authorized single-snapshot result `{reportId,studyId,summary}` from the latest report version. It must invoke the current qualified predicate and researcher RLS in the same read as the public V2 summary. If the newest version is withheld, do not silently fall back to an older report. The export endpoint must perform its own fresh read and return no file after consent withdrawal, deletion, source revision or policy invalidation. A prior successful page response cannot authorize a later export.
