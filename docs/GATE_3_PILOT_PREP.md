# Gate 3 pilot preparation

This is a synthetic rehearsal plan for an open, profile-matched marketplace. Gate 1 redaction qualification, the voice consent/data-handling decision and Gate 2 marketplace readiness must pass before Gate 3 fielding. No hand-recruited or invitation-selected first-study cohort is assumed.

## Probe timing evidence

For each eligible core-question answer, record upload confirmation, transcription completion, decision, and browser render times under a shared attempt ID. Classify every attempt as rendered, intentional no-probe, error or timeout. A late probe is discarded once the next question is active. Use `summarizeProbeOutcomes` for sample size, rendered p95 and separate outcome counts and rates. Time representative mobile browser recordings on physical iOS Safari and Android Chrome. Agree on an acceptable timeout rate before fielding; the six-second p95 applies from upload confirmation through browser render.

The AI-owned `decideProbe` advances to the next guide question on provider error, malformed output or timeout. Its turn ID protects against late results. The browser adapter must call `presentProbeIfCurrent` when mounting a probe and supply the same monotonic clock used at upload confirmation; the hook observes two animation frames and records render time. Count a superseded turn separately from an intentional no-probe decision. The eight-case fictional `probe-runtime` replay yields three rendered probes (p95 5,100 ms), one intentional no-probe, two errors, one timeout and one superseded turn. These fixture timings are labels, not measurements from a device or live provider.

The separate `probe-quality` replay now has 11 fictional answer/goal/decision labels: five acceptable neutral, on-goal probes, three expected next-question decisions, and three rejected probe examples (leading, off-goal and incomplete). The runner reports those categories independently. It also exercises a deterministic leading-question rejection in the runtime. These labels were authored as synthetic fixtures; they do not estimate live model quality. Before the PRD's probe-quality target is assessed, collect the planned 60 independently judged answer transcripts, define the neutral/on-goal rubric and disagreements, run the actual provider against held-out inputs, and report numerator, denominator and off-topic count.

## Report evidence and pilot record

Build the analyst from current qualified redacted projections only. Recheck every citation at report and export read time. Record candidate, accepted and dropped evidence counts and reason categories without logging transcript text. Verify theme counts against hand labels, hypotheses, confidence rules and the proposed next study on fictional fixtures. A database-backed IT-3.2 must cover deletion, withdrawal and re-redaction. The eventual pilot record should show the actual marketplace signup, profile verification, match, screener, acceptance, submission and approved-complete denominators by study, plus researcher and respondent counts, consent versions, report timing, and PRD section 12 metrics. The 30 to 50 respondent and 2 to 3 researcher target remains a planning target until Gate 2 updates the shared plan. These are unmeasured until sequential acceptance opens.

The report must use an authoritative study-level approved-complete denominator supplied by Platform, with each counted respondent represented once and only current qualified redacted evidence cited. It must not infer sample size from visible quotes, matched profiles, invites, submitted answers, payouts or the purchased target. A study that has not filled can still have valid approved completes; whether a partial report is publishable is an explicit Platform/product policy, not an analyst inference. The researcher price is $2 per billed core question per respondent, the respondent reward is $1 per answered core question, and an unfilled study refunds the non-completing respondent slots proportionally (for example, 12 purchased and 11 completing refunds one slot). Those amounts belong to deterministic checkout/payout contracts, not report text generation. The $5 referral reward after five verified profiles also belongs to Platform, not to the analyst or probe.

Gate 2 must define one auditable `approvedComplete` predicate for both report denominators and fill/refund settlement: how the quality hold, replacement, duplicate respondent, withdrawal/deletion, cancelled or expired session and partial answered-question reward affect that predicate; when the settlement snapshot freezes; and whether later invalidation changes a previously delivered report or refund. The report reader needs the resulting `studyId`, `targetRespondents`, current `approvedCompleteCount`, qualified source/version membership and report publication state in one authorized snapshot or equivalent provenance. Keep this metadata private unless the approved public report contract explicitly includes it. Gate 2 and Gate 3 must agree whether public V2 `themes[].total` means all approved completes or only qualified respondents who answered the relevant question, then check it against the authoritative eligible denominator at publication and recheck/invalidate when source membership changes. An unfilled study must not be mislabeled as fully complete in the researcher view.

## Adapter handoff after qualified report PR #132

The following is an implementation checklist for the Gate 2 Platform transaction and the later Gate 3 report/export reader. It does not enable publication.

1. Load the report, study, ordered findings and stored quote rows in one transaction. Bind each V2 theme index (1-based) to `finding.position`, then bind that finding ID to its qualified claim and exact verified quote set. Reject a missing, duplicate, extra, reordered or other-study finding or quote. The report and all cited sources must belong to the same authorized study.
2. For each candidate, load the current Gate 1 qualified redacted projection, active policy and publication receipt, consent, withdrawal and deletion state. Verify the immutable source UUID, Unicode span and exact text. Recheck immediately before commit. A same-text re-redaction must invalidate the old UUID.
3. Store proposal provenance, private rationale, model/prompt version and actor in the restricted append-only audit. Record accept, edit or drop with causation, including rejected candidates and retry behavior. Do not return rationale or proposal metadata through the public V2 shape, report or export.
4. Qualify every public free-text field (executive answer, claim and hypothesis) with the active Gate 1 redactor. Pass the exact verified quote map and qualified output to the restricted publication RPC. If any qualification, source check, audit write or RPC assertion fails, publish nothing.
5. Read report and export through the same current-report predicate and researcher RLS view. Re-evaluate consent, deletion, source revision, active policy and the complete immutable content digest at read time. Never assemble an export from raw report/finding/quote tables or a previously authorized snapshot.
6. Database-backed IT-3.2 should exercise cross-study and swapped-position quotes, missing/extra membership, private audit visibility, PII planted in all public text fields, same-text re-redaction, consent withdrawal, deletion, policy revocation, and a change between verification and commit. API and export reads must both withhold stale content.

PR #138 composition interface: pass `publishReviewedFromQualified` as PR #132's `publishQualifiedThemeSet` `ports.publish` callback. Its `loadReport(reportId)` must return the current authorized `{reportId, studyId, findings:[{id,position}]}` snapshot. The bridge checks positions and review-to-public quote membership, then calls PR #138's `publishReviewedReport(reportId, content, findingIds, policy, reviews)`. The restricted RPC remains the final authority for stored quote membership and current source qualification. The bridge requires a caller-supplied reviewed decision for every approved quote and keeps dropped proposals private. The `reviews` input carries proposal/causation IDs, private candidate/rationale, model and prompt versions, actor, action, position and approved quote. It must come from a restricted reviewer workflow, never from a researcher-facing request body. The real `loadReport`, qualified redactor/quote verifier and export reader are still Platform handoffs.

For researcher report display, `readReportDisplay` accepts only a fresh `QualifiedReportReadPort.readCurrent(studyId)` result from a single consistent read through `internal.gate3_report_current` and researcher RLS. It strictly checks the public V2 shape, study IDs and quote provenance; an absent, malformed or failed read clears the displayed report and disables export. The UI should show a neutral “Report currently unavailable” state with a retry action, without retaining earlier claims or quotes. A ready state may show the executive answer, ordered themes, supporting and contradicting quotes, confidence and hypotheses. The download action must call `exportCurrentReport` or an equivalent endpoint that repeats the qualified predicate at request time; it cannot serialize the cached page state. No report/export endpoint or page is mounted yet because the required current-read transaction is absent from the Platform handoff.

`ReportUiController` and the unmounted researcher `StudyReportPanel` now implement those states against an injected `readCurrent` port. Refresh clears prior text while it checks; an older response cannot restore content after a newer withheld result. Export re-reads and disables the button during the check. If a newer report version appears, it displays that version but requires a second click after review before downloading. Fixture tests exercise ready→withheld, overlapping refreshes, malformed/private payloads and a new version. The panel is deliberately not mounted on `StudyTrackingPage` until Gate 2 supplies the authorized current reader/API; this avoids showing a permanent unavailable section or inventing a public route.

## Probe state-machine handoff

`beginProbeTurn` and `advanceProbeState` model one answer's upload, transcription, decision and render with a unique turn ID, probe cap and deadline. Provider or transcription failure advances to the static next guide question. Current `InterviewView`/`AnswerComposer` only receive `SessionResponse.nextQuestion` and call `onSaved()` to reload the next core question. To integrate, Platform must expose a probe-aware, idempotent answer/turn read and decision write bound to `sessionId`, `guideQuestionId`, `answerId`, current transcript job/source revision, `maxProbes`, probes used, deadline, `probeId`, decision status and shown timestamp. The write must reject a decision for a superseded answer or question, a duplicate probe beyond the cap, and a result after the deadline. The respondent API should surface one current prompt (probe or next core question) with stable turn ID; browser code can then call `presentProbeIfCurrent` after confirmation and record the paint time. The upload confirmation and browser mark must use the same monotonic clock. Gate 1 consent and transcript availability still govern provider input. Until those fields and transitions exist, the synthetic state machine is not an integrated interview path.

The typed `ProbeDecisionPort` now defines `readReadyTurn`, compare-and-set `commitDecision`, and `markShown`. `readReadyTurn` must return a server-clock deadline, server upload confirmation time and transcript ready time; a separate browser monotonic confirmation time is echoed for the same-page render metric. It must also return the exact authorized model request and immutable transcript revision. Gate 3 re-reads and compares that snapshot after the provider returns, then commits only through the Platform compare-and-set. `markShown` receives the browser render measurement but must set database `shown_at` from the server clock after verifying the probe is still current. Browser and server timestamps must never be subtracted from one another. A page reload or a different device clock needs a fresh timing attempt or an unmeasured classification. The current Gate 1 APIs do not expose these fields or persist a probe decision; this remains a precise Platform request.

The port also needs `readCommitted(sessionId, turnId)`, scoped to a still-current authorized turn, returning `{sessionId,questionId,answerId,turnId,transcriptRevision,decision,probeId}`. A repeated delivery must return that decision without calling the model again. If another worker commits while one model call is pending, re-read the first writer's result and do not replace it. `commitDecision` must compare the session/question/answer/turn, immutable transcript revision, probe cap and deadline and be idempotent on the same key. It returns either the exact persisted decision and probe ID, `stale`, or `unavailable`; an uncertain write must not show generated text. `markShown` must be idempotent and reject a superseded probe. Gate 2 owns the contract, persistence and respondent UI, while Gate 3 owns this AI orchestration and will review the integration.

The browser presenter checks the active turn before mounting, waits for paint, then calls `markShown`. If the receipt is stale or unavailable it invokes the supplied retract callback and counts the attempt as superseded/error rather than rendered. The respondent UI must actually remove that probe on retraction and advance or retry according to its persisted current prompt; a stale receipt cannot leave text on screen.

The qualified report read port needs an authorized single-snapshot result `{reportId,studyId,summary}` from the latest report version. It must invoke the current qualified predicate and researcher RLS in the same read as the public V2 summary. If the newest version is withheld, do not silently fall back to an older report. The export endpoint must perform its own fresh read and return no file after consent withdrawal, deletion, source revision or policy invalidation. A prior successful page response cannot authorize a later export.

Gate 2 draft PR #138 now exposes `loadCurrentQualifiedReport(db, studyId)` with this exact shape and a newest-version-first database read. Gate 3's `currentQualifiedReportPort(db, loadCurrentQualifiedReport)` structurally connects it to `ReportUiController` using an authenticated request-scoped client. The browser-facing `reportBrowserPort` expects a future no-store `GET /api/researcher/studies/{studyId}/report` that invokes that loader on every request. Both display and export call this endpoint afresh. No route is mounted yet; Gate 2's stacked service must land and the Gate 1 qualification handoff must pass before the page uses it.

The 60-answer held-out probe workflow and a synthetic-only pipeline smoke command are documented in `packages/ai/evals/PROBE_HELDOUT.md`. The synthetic score must never be reported as independent model quality.

## Draft voice and AI disclosure handoff

Rachel's `envoi-terms-draft-v0.1.md` is counsel-pending source material, not consent approval or a published policy. Its long notice names AI follow-ups and analysis, but its consent screen writes only `recording`, `transcription_vendor`, `retention`, `researcher_access` and optional `voice_clip_sharing`. Gate 2's draft probe ledger checks a separate `ai_followup` purpose and returns qualified `transcript.redacted_text` plus the guide question to a server-only request builder; the current onboarding has no `ai_followup` grant path. The Gate 3 runtime now refuses a request whose purpose is not `ai_followup`, but that string check is not proof of consent. The Platform read/commit must enforce the current grant and immutable source receipt before any provider dispatch. Live probes remain disabled.

**Proposed screen text for Rachel and counsel to review:** “To choose a short follow-up question, we send the text of your answer, after automated personal-detail removal, and the relevant study question to our AI follow-up provider. We do not send your voice recording to that follow-up model. [Provider and data-use details.]” Put an unchecked, purpose-specific agreement beside this text: “I agree to this AI follow-up use of my interview text.” If participation requires that agreement, state that consequence plainly; if a fixed-question path is allowed, state that instead. The draft must name the actual provider and verified retention/training terms before it can make either promise. The transcription agreement should separately name audio transfer to the primary and backup speech providers and should not imply that redaction happens before transcription.

**Proposed report-analysis disclosure for review:** “We use text with detected personal details removed to create study findings and reports. Our AI analysis provider may receive that text and the study questions. A reviewer checks proposed findings and quoted excerpts before a report is made available.” If analysis is sent to an external model, add a versioned `ai_analysis` purpose or obtain an explicit approved equivalent; `researcher_access` alone describes what the researcher receives, not the model transfer. Do not enable this path until the recipient, purpose, consent and qualified-source policy are approved. Keep any optional use of de-identified transcripts to test or improve interview questions as a separate, versioned purpose; the draft's secondary-use sentence is not implemented by the Gate 3 ports. Distinguish a provider's inference request from using data to train its model, and verify provider settings/contracts before stating that no provider trains on data or retains requests.

**Proposed report/export disclosure for review:** “Researchers can view redacted answers and verified excerpts for their studies and download the current report. Withdrawal, deletion or a new redaction can remove a report from future viewing and download. A file a researcher already downloaded cannot be recalled.” Gate 3's browser port only prepares a future JSON download and re-reads the newest currently qualified report for every display/export; no PDF, CSV footer, voice-clip download or authenticated report endpoint is implemented here. Do not promise a format or revocation behavior beyond what the deployed path proves. The public report must omit private candidate rationale, respondent profile, contact details and raw media; the restricted review audit may retain proposal provenance under its approved retention policy.

**Exact Gate 2/Gate 1 fields and checks needed:** store separate consent decisions with `respondentId`, `studyId` or explicitly account-wide scope, `purpose`, `granted`, `textVersion`, `eventId`, `decidedAt` and a stable text/policy digest. The `ai_followup` purpose must bind the approved provider disclosure and current immutable redacted-source receipt to the probe turn. The server-only ready read should return an authorization receipt ID/digest and source version for audit, while keeping transcript text out of browser responses; every ready read, commit and shown receipt must recheck the current grant and invalidate after withdrawal or a newer receipt. For external analysis, the report publisher must verify the approved `ai_analysis` purpose or policy equivalent for every cited source and record model/prompt/provider version in private audit, then recheck consent and source qualification at publication and every current read. Gate 1 owns actual transcript qualification and retention; Gate 2 owns consent schema, UI, service and database contracts. The terms' 60-day/24-month and provider-training assertions require separate verification before policy activation.

The unmounted panel uses a named section, ordered headings and live status text for loading, withholding and changed-version review. A withheld export now shows only the unavailable state; the changed-version notice appears only when a different *ready* version requires review. Its loading section is marked busy. These source checks do not establish rendered accessibility.

Once Gate 2 supplies the authenticated `GET /api/researcher/studies/{studyId}/report` backed by `loadCurrentQualifiedReport` and Gate 1 qualification is approved, mount the panel in an isolated test route with fictional current and withheld responses. Run an axe browser scan for loading, ready, withheld and newer-version states; require zero critical or serious violations. Also verify keyboard focus and order for Check again and Download report, disabled export during a fresh read, screen-reader announcement of state changes, 200% zoom/reflow, and contrast in the actual theme. Check that a ready-to-withheld transition removes the old executive answer and citations from the DOM and that a stale earlier response cannot restore them. After a denied export, no file download may occur; after a new ready version, the first click must request review and the second must perform another qualified read before downloading. Use a fresh browser response for every display and export check. No axe package or mounted authorized route exists in this branch, so this remains a prepared acceptance check rather than a passing browser result.
